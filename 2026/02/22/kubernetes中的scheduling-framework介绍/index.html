kubernetes中的scheduling-framework介绍

本文将介绍下Kubernetes中的调度框架（Scheduling Framework），Scheduling Framework是一种用于Kubernetes调度器的插件化架构。

基本介绍

Scheduling Framework定义了一些扩展点，调度插件可以通过这些扩展点来实现调度功能。

每个Pod的调度分为调度周期（scheduling cycle）和绑定周期(binding cycle)两个阶段。调度周期用于给Pod选择一个节点。绑定周期用于将调度结果应用到集群中。一个调度周期和绑定周期被称为调度上下文（scheduling context）。调度周期是串行调用的，而绑定周期可能并行运行。

下图显示了一个Pod的调度上下文以及调度接口。

扩展点

PreEnqueue

PreEnqueue接口在Pod加入到内部的active队列之前调用，只有当所有插件都返回Success时，Pod才会放到active队列中。通常用于避免不满足要求的Pod进入调度阶段，从而减少不必要的开销。

触发条件：在Pod进入调度队列之前

返回状态：

状态码 描述
Success 所有插件都返回成功时，Pod放入active队列。
Error 不再继续后续的调度。

EnqueueExtensions

EnqueueExtensions接口用于在集群状态发生变化时，控制是否重新调度被插件拒绝的Pod。通常实现了PreEnqueue、PreFilter、Filter、Reserve或Permit的插件需要实现此接口。

QueueingHintFn

QueueingHintFn是一个回调函数，可以决定Pod是否可以重新放入active队列或者backoff队列。

QueueSort

QueueSort接口用于给调度队列中的Pod排序。注意调度器只能使能一个排序插件。

PreFilter

PreFilter接口用于预处理Pod的信息，如果PreFilter接口返回错误，调度周期会终止。

触发条件：在Pod进入调度周期后

返回状态：

状态码 描述
Success 所有插件都返回成功时，进入下一阶段。
Error 预过滤错误，结束当前阶段。
Unschedulable 预过滤拒绝，继续调用其他插件。
UnschedulableAndUnresolvable 预过滤拒绝，结束当前阶段。
Skip 跳过后续的Filter阶段。

Filter

Filter接口用于过滤掉Pod无法运行的节点。调度器会针对每个节点，依次按照插件配置顺序调用，如果任意一个插件拒绝，剩下的插件不会继续调用。多个节点的过滤可能并行。

触发条件：在所有PreFilter调用成功后

返回状态：

状态码 描述
Success 通过所有插件过滤的节点为备选节点。
Error 过滤错误，结束当前阶段。
Unschedulable 过滤拒绝，不再进行其他插件的调用。
UnschedulableAndUnresolvable 过滤拒绝，不再进行其他插件的调用。
Pending 过滤拒绝，不再进行其他插件的调用。

PostFilter

PostFilter在Filter接口调用之后，但是只有在没有可用节点的情况下会调用。插件会按照配置顺序调用，如果有一个插件返回Schedulable，剩下的插件不会继续调用。一般PostFilter接口用于实现抢占功能。

触发条件：Pod没有可调度的节点

返回状态：

状态码 描述
Success 有一个插件返回成功后，结束当前阶段。
Error 后过滤错误，结束当前阶段。
Unschedulable 继续下一个插件调用。
UnschedulableAndUnresolvable 后过滤拒绝，结束当前阶段。
Pending 继续下一个插件调用。

PreScore

PreScore接口在打分阶段之前调用，通常用于为打分插件生成共享的数据。如果PreScore接口返回错误，调度周期就终止了。

触发条件：Filter阶段成功执行后

返回状态：

状态码 描述
Success 所有插件都返回成功时，进入下一个阶段。
Error 结束当前阶段，不再调用其他插件。
Skip 跳过后续Score阶段调用。

Score

Score接口用于给过滤后的节点打分。调度器通过调用各个打分插件，最终生成一个指定范围内的分数。在NormalizeScore阶段，调度器会根据各个插件的权重计算出最终的得分。

触发条件：所有PreScore插件调用成功

返回状态：

状态码 描述
Success 所有插件都执行成功后，进入下一阶段。
Error 打分错误，结束当前阶段。

NormalizeScore

NormalizeScore接口用于在调度器计算节点最终得分前进行分数归一化。

触发条件：在Pod进入active队列之前

返回状态：

状态码 描述
Success 所有插件都返回成功时，进入下一阶段。
Error 分数归一化错误，结束当前阶段。

Reserve

Reserve接口分为Reserve和Unreserve两个方法，Reserve接口在选好节点后用于预留资源，Unreserve会在预留资源的Pod被拒绝时或者在调用预留插件过程中出现错误时被调用。

触发条件：在选择好调度节点后

返回状态：

状态码 描述
Success 所有插件都返回成功时，进入下一阶段。
Error 预留错误，结束当前阶段。
Unschedulable 预留拒绝，结束当前阶段。
UnschedulableAndUnresolvable 预留拒绝，结束当前阶段。
Pending 预留拒绝，结束当前阶段。

Permit

Permit阶段通常在调度周期的最后阶段调用，用于阻止或者延迟绑定候选节点。Premit插件有3种结果，approve表示Pod进入绑定阶段，deny表示Pod重新回到调度队列。wait表示Pod处于等待状态。

触发条件：在进入绑定周期前调用

返回状态：

状态码 描述
Success 所有插件都返回成功时，进入下一阶段。
Error 准入错误，结束当前阶段。
Wait 进入等待状态，需要其他插件没有拒绝。
Unschedulable 准入拒绝，结束当前阶段。
UnschedulableAndUnresolvable 准入拒绝，结束当前阶段。
Pending 准入拒绝，结束当前阶段。

PreBind

PreBind接口用于执行绑定前的动作。例如可以执行网络/存储的准备动作。如果任意的插件返回失败，Pod就会被拒绝。

触发条件：进入绑定周期时调用

返回状态：

状态码 描述
Success 所有插件都返回成功时，进入下一阶段。
Error 预绑定错误，结束当前阶段。
Unschedulable 预绑定拒绝，结束当前阶段。
UnschedulableAndUnresolvable 预绑定拒绝，结束当前阶段。
Pending 预绑定拒绝，结束当前阶段。

Bind

Bind接口用于将Pod绑定到节点上，绑定插件会按照配置顺序依次调用，插件可以选择是否处理，如果有一个插件处理了，剩下的插件都会被跳过。

触发条件：所有PreBind插件都调用成功

返回状态：

状态码 描述
Success 只要有一个插件成功时，就进入下一阶段。
Error 绑定错误，结束当前阶段。
Unschedulable 绑定被拒绝，结束当前阶段。
UnschedulableAndUnresolvable 绑定被拒绝，结束当前阶段。
Skip 当前插件不处理，继续调用其他插件处理。
Pending 绑定被拒绝，结束当前阶段。

PostBind

PostBind接口在Pod绑定节点成功后执行，通常用于清理相关的状态或资源。

触发条件：在Pod绑定成功后调用

返回状态：无

总结
