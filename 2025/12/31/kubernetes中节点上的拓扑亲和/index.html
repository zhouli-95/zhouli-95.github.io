kubernetes中节点上的设备拓扑亲和

之前的文章介绍了kubelet和device-plugin之间的交互机制，从之前的文章可以发现kubelet在分配设备之前会先计算亲和性，本文将介绍下kubelet中设备拓扑亲和性相关的机制。

基本介绍

工作流程

首先大致看下kubelet中topogoly manager的工作流程。

  1. Kubelet收到Pod创建请求后，调用Topology Manager来判断Pod是否允许准入。
  2. Topology Manager依次调用CPU Manager，Device Manager, Memory Manager来获取Topology Hints。并计算得到最佳Topology Hint。
  3. Topology Manager返回准入成功后，开始调用上述Manager来分配资源。
  4. 分配资源成功后，Kubelet开始创建并启动容器。

scope

目前Topology Manager支持以下几种作用域。

作用域 描述
container 默认作用域，以container为单位进行拓扑计算。
pod 以pod为单位进行拓扑计算。

policy

目前Topology Manager支持以下几种分配策略。

策略 描述
none 默认策略，不执行任何拓扑对齐。
best-effort 尝试寻找最佳的NUMA节点对齐，如果没有找到，仍会调度Pod
restricted 尝试寻找最佳的NUMA节点对齐，如果没有找到，会拒绝Pod
single-numa-node 要求所有资源必须来自同一个NUMA节点，如果不满足，会拒绝Pod

代码分析

直接从calculateAffinity函数入手，首先调用了accumulateProvidersHints函数获取了所有的亲和提示，然后调用对应策略的Merge函数来获取最佳亲和配置。

accumulateProvidersHints函数中调用了所有hintProviders的GetTopologyHints函数，然后把结果保存到数组。

设备的亲和提示实现在devicemanager中。

  1. 首先调用了UpdateAllocatedDevices函数用于更新已分配的设备列表。
  2. 然后调用getContainerDeviceRequest函数获取所有设备资源的请求数量。
  3. 调用deviceHasTopologyAlignment函数判断设备是否支持NUMANode拓扑。
  4. 调用containerDevices函数获取当前容器已分配的设备信息allocated。如果大于0，说明之前已经分配，用allocated重新生成拓扑。
  5. 调用getAvailableDevices函数获取可用的设备available。
  6. 最后调用generateDeviceTopologyHints函数生成设备拓扑提示。

generateDeviceTopologyHints函数中，主要逻辑是遍历所有NUMA组合，根据设备拓扑计算出满足的亲和提示列表。

  1. 首先根据NUMA节点进行组合遍历，比如有0，1两个NUMA节点，那么会遍历 01，10，11三种情况。
  2. 在遍历NUMA组合时，计算出满足NUMA亲和条件的最少的NUMA节点数量minAffinitySize。
  3. 在遍历NUMA组合的同时遍历设备，判断当前设备的NUMA是否落在遍历组合上，如果满足，累加numMatching，直到numMatching大于等于设备请求数量request后，将该种遍历组合保存到亲和提示hints中。
  4. 最后遍历所有满足的hints，如果hint中的NUMA数量和minAffinitySize相等，把hint中的Preferred设置为true。

然后看下Merge函数的实现，这里以best-effort策略为例。首先调用了filterProvidersHints函数来过滤，然后调用Merge函数来得到bestHint。

filterProvidersHints函数里遍历所有的providersHints，将不同资源的hints合并到allProviderHints数组。

Merge函数里，遍历上面过滤后的所有TopologyHints的组合情况，然后调用mergePermutation函数处理每种组合，最后通过compare函数比较获得最佳拓扑亲和bestHint。

mergePermutation函数里遍历了所有的TopologyHints,并将NUMA亲和保存到numaAffinities中，然后取所有numaAffinities的交集mergedAffinity。另外只有所有的TopologyHint都是最优时，最终mergedAffinity才是最优的。

compare函数用于比较两种TopologyHint哪种更优，这里实际情况比较复杂，先不具体介绍了。

CompareNUMAAffinityMasks函数中默认选择占用NUMA节点最少的TopologyHint。

然后再介绍下filterByAffinity函数，因为在这里会根据上面计算出的最佳拓扑亲和来选择设备。

  1. 遍历所有可用设备列表available，并根据NUMA分类保存到perNodeDevices中。
  2. 将所有的NUMA的编号保存到nodes数组中，并按照node是否在最佳拓扑亲和中对数组进行排序。
  3. 遍历所有可用设备列表available和所有的NUMA节点nodes，如果设备没有NUMA信息，保存到withoutTopology中，如果设备的NUMA满足最佳拓扑亲和加入到fromAffinity中，否则加入到notFromAffinity。

总结

本文介绍了kubelet中设备拓扑亲和性相关的机制，主要是拓扑管理器调用各个管理器来获取拓扑提示，然后计算出最佳的拓扑提示，最后管理器在分配时可以根据最佳拓扑来选择资源分配。
