kubernetes中的device-plugin的基本介绍

本文将介绍下kubernetes中device plugin机制，以及如何实现一个简单的设备插件。

基本介绍

什么是device plugin

device plugin是kubernetes官方提供的一种设备插件机制，用于支持不同的厂商注册各自设备到kubernetes集群。

为什么需要device plugin

由于不同的场景需求，用户在kubernetes集群中可能需要使用不同类型的设备，比如GPU设备，网卡设备等。而这些不同类型的设备一般由不同的厂商设计实现，不便直接集成到kubernetes中。因此kubernetes官方设计了一种设备插件机制，用于对接不同厂商的设备。kubernetes官方通过定义统一的设备插件框架，规范了设备使用的方式，也降低了设备接入kubernetes集群的难度。

使用示例

在kubernetes中当Pod需要设置cpu或内存的大小时，一般是在Pod规格的requests和limits中声明。

设备资源的使用也是类似，假设我们注册了一种名为 example.om/demo 的设备，那么只需要在Pod规格中的requests或limits中加入该设备的声明即可使用。

插件注册

首先我们先进行了设备插件的初始化。初始化主要分为两个步骤，第一步是启动grpc服务端用于提供DevicePlugin接口服务。第二步是连接kubelet并把grpc server注册到kubelet中。

设备列表

设备注册之后，kubelet会调用设备插件的ListAndWatch接口用于获取设备的列表和状态。同时设备插件可以持续监控设备的状态并上报给kubelet。kubelet会根据健康状态来决定更新节点的可用资源。这里简单的构造了设备列表用做示例。

设备分配
